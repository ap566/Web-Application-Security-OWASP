# Security Lab Demo Walkthrough

## Purpose

Demonstrate one vulnerability in an intentionally vulnerable training lab, explain its impact, apply or describe the appropriate fix, and show the retest result.

## Before recording

- Use a PortSwigger Web Security Academy lab or another intentionally vulnerable local training application.
- Confirm the lab is within the permitted scope.
- Close unrelated browser tabs and hide personal notifications.
- Do not show real accounts, passwords, session cookies, tokens, or private information.
- Prepare the report and screenshots with sensitive values redacted.

## Suggested recording structure

### 1. Introduction

- State the lab name and learning objective.
- Explain that the demonstration is limited to an authorized training environment.

### 2. Application behaviour

- Show the relevant page or feature.
- Explain the expected normal behaviour.

### 3. Vulnerability identification

- Name the vulnerability and corresponding OWASP category.
- Explain the root cause at a high level.

### 4. Controlled test

- Demonstrate the lab's permitted test procedure.
- Show the result and explain what it proves.
- Avoid testing any unrelated system or account.

### 5. Remediation

- Explain the secure coding or configuration change.
- Show a safe code example or the relevant defensive setting when available.

### 6. Retest

- Repeat the normal test after the fix, if the lab supports it.
- Show whether the weakness is resolved.
- Record any remaining limitations.

### 7. Conclusion

- Summarize impact, fix, and lessons learned.
- Point to the written vulnerability report.
