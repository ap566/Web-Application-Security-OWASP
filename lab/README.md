# Safe Web Application Security Lab

## Approved practice environment

Use intentionally vulnerable training labs such as [PortSwigger Web Security Academy](https://portswigger.net/web-security). Read each lab's instructions and remain within its stated scope.

Only test systems that you own or for which you have explicit permission. Do not scan, probe, exploit, or attempt to access real websites, accounts, or data without authorization.

## Workflow

### 1. Identify

- Select a training lab and record its name.
- Read the learning objective and scope.
- Identify the feature and expected behaviour.

### 2. Test

- Follow the lab's permitted instructions.
- Make the smallest test needed to demonstrate the issue.
- Record the observed result and redact sensitive values.

### 3. Fix

- Identify the root cause.
- Select a defensive coding or configuration change.
- Explain why the change prevents the weakness.

### 4. Retest

- Repeat the relevant test where a fixed application is available.
- Record pass, fail, or not performed.
- Do not claim a fix was verified when no retest occurred.

### 5. Document

Create a report using [the vulnerability report template](../reports/Vulnerability-Report-Template.md). Store only sanitized screenshots and notes.

## Safety and privacy

- Never commit passwords, API tokens, session cookies, private keys, or personal data.
- Do not publish unredacted HTTP requests or responses containing credentials.
- Keep practice within the lab's authorized scope.
